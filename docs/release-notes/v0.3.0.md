## Install

Download `ecamm-mcp.mcpb`, double-click it, click Install in Claude, then click Allow in Ecamm Live. Check the file against `SHA256SUMS.txt` if you like: `shasum -a 256 ecamm-mcp.mcpb`.

Updating from 0.2.x: install over the old one, then quit Claude completely (Cmd+Q) and reopen it.

## What changed

**Going live and recording are now by stated intent.** "Go live", "record" and "end" say where you want to end up, so a repeated "go live" no longer risks ending the show, and "go live" in Record Only mode is refused. The result is read back from Ecamm and reported as verified, failed or unknown.

**API corrections and fixes**
- Markers now use the command Ecamm acts on. Through 0.2.3 a marker request was accepted and silently dropped.
- Pause and resume, system audio and Zoom sharing use the reviewed API names. System audio and Zoom sharing still need real-device verification.
- Setting a volume no longer reports a failure when Ecamm answers with the level.

**New**
- Scene sheet: one labeled picture of every scene, with an explicit refresh that returns to where you were.
- Overlay text: change the text of an existing text overlay.
- Cues: check, then run, up to 12 ordinary steps in order. A cue cannot go live, record, end or post.
- The pre-show check no longer says "ready". It reports what it saw, what it could not read, and what it never checks.
- Changes to Ecamm now run one at a time, in order.
- `SHA256SUMS.txt` with every release. The Terminal installer now requires it and installs nothing if it is missing or doesn't match, so it can no longer install 0.2.x.

**Optional and experimental, off by default: recording files.** Same package, nothing to install separately. Tools that read a recording folder you choose: marker files, media metadata, an edit receipt. Metadata inspection needs `ffprobe`; browsing and notification capture do not. Configuration is manual. The completion Shortcut is experimental: test runs were captured but the Shortcuts runner did not exit, and it has not fired from a real recording. Ignore them if you only want to run Ecamm.

## Known gaps

- **Go live from this version is unconfirmed.** It worked on 0.2.x. One attempt on an earlier development build, from Ecamm's `New` button, did not start a broadcast and was reported as unknown. Record, pause, resume, one split and end were seen working once each on a development build.
- **Untested against a real Ecamm:** video playback, audio filters, Profile switch, Zoom sharing and meeting controls, system audio and guest audio buses, controlling Ecamm on another Mac, and most of the recording-file tools. The verification matrix lists each tool's evidence.
- **English only.** If Ecamm isn't in English, it will refuse to go live, end or refresh scene pictures.
- **After changing extension settings, quit and reopen Claude.**

## What Ecamm's API can't do

The reviewed HTTP API does not provide a full chat feed, event subscriptions, scene-layout authoring, an independent on-air signal, or a recording-completion path. Scene switching and existing overlay-text editing are supported. Ecamm’s separate Shortcuts completion event is the experimental path used by our recording helper. See the README for the scoped limitations.

Ecamm Live is Mac-only. Any "Ecamm for Windows" repo is not this project and is not from Ecamm.
